# Fix: mid-stream SSE drops kill ACP turns with an opaque error

## Diagnosis (confirmed by reading the code)

The error chain, inside-out: the model gateway sends HTTP 200 and starts streaming; mid-stream the connection drops / body is truncated → reqwest `Decode` error ("error decoding response body") → `eventsource_stream` wraps it as "Transport error" → `o3gen-openai/src/lib.rs:176` collapses **every** SSE error into `ApiError::Builder("SSE error: ...")` → two nested thiserror wrappers each prepend "API error:" → ACP turns it into `-32603 Internal error`.

Why it's fatal and uninformative:
1. `agentsdk/src/core/agent.rs:827-828` — the chunk loop does `acc.push(&chunk?, ...)`, so a mid-stream error bubbles straight out of `Agent::run`. `stream_with_retry` (line 971) only guards stream *establishment*, and the error never reaches the `on_api_error` plugin hook.
2. Even if it did, pie's `StreamPlugin::on_api_error` (`pie/crates/pie-core/src/agent/stream.rs:284-286`) gives up on any error without an HTTP status — and `ApiError::Builder` has none.
3. pie's `AppError::Api` (`pie/crates/pie-core/src/error.rs:25`) adds the second "API error:" prefix.

Retry is **safe**: `ModelResponseAccumulator::push` only commits the assistant message to History on `finish_reason`, and tools execute only after the stream completes — so a dropped stream leaves history untouched and nothing half-executed. Only text deltas already forwarded to the client are lost, which a re-request regenerates.

Going with: fix both repos; retry always within the existing `[agent.retry] api_error` budget; keep provider-agnostic (better logging will reveal the upstream gateway).

## Changes — agentsdk (`~/src/pie/agentsdk`, sibling path dep)

1. **`crates/o3gen-openai/src/lib.rs` (`stream_chat`)** — stop collapsing SSE errors. Match on `eventsource_stream::EventStreamError`: `Transport(e)` → `ApiError::Reqwest(e)` (the variant already exists in the generated enum — no o3gen template change), preserving reqwest diagnostics (`is_decode`, `is_timeout`, source chain). Parse/UTF-8 SSE errors stay `Builder` but with a clearer message ("SSE parse error: …").
2. **`src/core/agent.rs` (`run`)** — restructure chunk consumption into an attempt loop: consume the stream; on a chunk error, dispatch `dispatch_api_error` (the same hook `stream_with_retry` uses). `RetryAfter(delay)` → log, sleep, re-establish the stream, reset the accumulator (preserve any captured `usage`), continue. `GiveUp` → return the error. Bounded by the plugin's existing retry budget, same as establishment retries.
3. **Tests (deterministic → rust tests)**:
   - Truncated-body test (raw response with `Content-Length` longer than the body, then close → reqwest decode error): first attempt truncated, second attempt returns a full valid SSE stream → assert `Agent::run` completes with the second attempt's text, and the first failure classifies as `ApiError::Reqwest` (not `Builder`).
   - A plugin whose `on_api_error` returns `GiveUp` → run returns the error unchanged.
4. Expose `AgentSdkError::is_transport()` (reqwest decode/body/timeout/request errors) in `src/error.rs` for pie's policy.

## Changes — pie (this repo)

5. **`crates/pie-core/src/agent/stream.rs` (`on_api_error`)** — classify transport errors (`error.is_transport()`) as retryable within the `api_error.max_errors` budget, using the existing `api_error.retry_delay_secs` backoff (leave config as-is; add a TODO for a dedicated stream-retry knob if needed later). Add unit test: transport error → `RetryAfter` until budget exhausted → `GiveUp`.
6. **`crates/pie-core/src/error.rs:25`** — drop the doubled prefix: `AppError::Api` renders `{0}` so anycode sees one clean chain instead of "API error: API error: …".
7. **Logging** — `tracing::warn` the reqwest source chain + provider base URL on each transport retry so persistent drops point at the actual gateway.
